# VChart DSL v1 执行与验收计划

2026-11-07。状态：**源码、首跑及集中修复已完成，最终证据见 [验收记录](VCHART_DSL_ACCEPTANCE.md)**。规范见 [VCHART_DSL_DESIGN](VCHART_DSL_DESIGN.md)。目标是让 py-mermaid 的新文本语法完整表达正式 `py-visactor-vchart==0.1.1` 当前已支持的二维静态规格，覆盖全部68类型及 JSON 可表达的配置。

## 1. 交付物及边界

| 交付 | 必须结果 |
|---|---|
| 语言 | `vchart <type>`、属性/配置块、JSON完整值、table、纯值引用、axis/series、内联map/SVG |
| 兼容 | 严格JSON文本入口、Python spec API、七类旧Mermaid图表入口保持 |
| 覆盖 | 全部68实际注册类型；225原规格结构等价；派发与高风险条件源码登记，有限分支验证 |
| 集成 | 公开编译结果、render/arender与CLI；正常PyPI正式依赖，不增第三方包 |
| 安全/预算 | UTF-16来源位置、重复/冲突拒绝、引用展开预算、显式离线资源、owner线程 |
| 验证 | 原语法/来源对照、同spec绘制一致、多格式/三后端/安装与受影响旧回归 |
| 交付报告 | 独立第六轮，分组、每页最多12例，原始文件/SHA/失败证据可下载 |

这是新语法与接线任务。供应方的实际静态限制、此前22条Mermaid分支缺口分别保留，不把“新语法可写”标为“后端已扩展”。未增加标题、图例、任意组合、多区域、3D、动态回调或新布局算法的隐含需求。

## 2. 依赖与模块责任

运行依赖维持：`py-skia-canvas==0.1.0a18`、`py-visactor-elk==0.1.0`、`py-visactor-katex==0.1.0`、`py-visactor-vchart==0.1.1`。词法/解析/编译使用标准库，新增第三方运行依赖为零。Node/浏览器仅用于研发对照和报告QA，不进入生产。

单文件单owner，实施时按既有并行规范登记租约：

| 工作流 | 主要文件 | 边界 |
|---|---|---|
| root | 规范、类型/字段清单、依赖与状态、验证/报告工具 | 冻结联合候选和总验收，不与worker并写公共文件 |
| A 语法 | 新 `model/vchart_dsl.py`、`parsing/vchart_dsl/lexer.py`、`parser.py` | 输出冻结AST与原文span，不能执行绘制或读取外部资源 |
| B 编译 | 新 `compiler.py`、纯值展开、属性写入/数据/组件lowering | 输出精确spec、纯资源声明与source map，不复制统计或布局算法 |
| C 集成 | 现有model/provider/bridge、API/CLI、资源绑定 | 保持VChartModel身份、旧JSON分支、公开Canvas API与线程所有权 |

先固定 AST、span、编译结果和错误合同。共享 `model/vchart.py`、`vchart_bridge.py`、`api.py` 等由 C 唯一写入；其他模块通过约定接口工作。设计阶段仅列责任，未因本文件自动启动worker。

## 3. 执行顺序

### P0：来源与合同冻结

已有本轮设计清单记录68代表和225原规格，但完整选项审计待实施。先完成：

1. 固定当前工作树，不清理、不覆盖上一轮未提交改动；保存产品/工具/文档起点指纹。
2. 使用公开类型清单，与68代表、225固定spec严格对分母。分组中的26统计独立名称不再重复计算histogram/boxPlot。
3. 逐渲染器登记实际字段、嵌套字段、单位、默认、枚举、数据形状、资源依赖、异常和条件；注明 source 文件/函数/分支和正式发布源码身份。
4. 分类 `supported_static`、`static_ignored`、`disabled_only`、`unsupported`，对每条已实现能力列出拟用例。不能靠AST扫到一个字符串或fixture见过一个键就宣布完整支持。
5. 固定EBNF与本规范的歧义处理、数组构造模式、对象写入所有权、命名空间、严格JSON兼容及诊断精度；给AST/编译结果公共合同。

P0验收是资料与合同一致，不是新DSL绘制成功。

### P1：一次完成全部源码接线

集中完成lexer、parser、AST、compiler、source map、table/引用、属性块/路径、axis/series、内联map/SVG、预算、安全、API/CLI和旧分支接线。对全部68类型复用相同编译管线，不按图种循环“写一个、测一个、验收一个”。

允许编译/import/签名/注册等机械检查。P1状态为 `code_complete_unverified`，不提前运行完整功能测试或把示例能执行当作全量门禁。生产只调用正式依赖的公开接口。

### P2：来源测试和对照设计

全部P1源码就绪后再集中编写：

| 测试组 | 用例与独立预期 |
|---|---|
| lexer/parser | 字符串/转义/注释/Unicode/BOM、括号、换行/分号、表头、关键字与属性名区分；手写AST/span预期 |
| 编译结构 | 225原spec→独立格式器产生DSL→编译结果按JSON类型严格等价；保留数组顺序、空容器、null、bool/int区别 |
| 手写语言特性 | 不依赖上述自动格式器，独立覆盖table、let、路径、块、索引、axis/series、资源和组合示例；手写golden spec |
| 字段/条件 | P0逐条静态能力映射，含histogram/boxPlot双数据分支、common双轴/非法系列、label禁用限制、固定尺寸等 |
| 负控 | 重复/父子冲突、数组洞、引用前置/重绑、table列数、非法数值、超额展开、资源冲突/外链及伪成功白图 |
| 错误位置 | 原始行列/UTF-16偏移，含非BMP字符、转义、变量声明与使用；Provider无结构错误不得捏造精确字段 |
| 旧兼容 | 严格JSON错误/注释禁止、Python对象API、七语法、现有注册顺序和错误路由 |
| API/CLI | compile/render/arender、当前event loop、实际参数/返回/错误、资源隔离和输出不覆盖输入 |
| 绘制/导出 | 同spec API与DSL在各后端实际内容/几何一致、PNG/JPEG/WebP/SVG/PDF、资源、图形/文字可见性 |
| 安装 | wheel/sdist新环境正常PyPI解析；68类型、代表导出与数学/ELK、无相邻源码/Node/Skia-Python回退 |

源规格字段中出现已静态排除的动画/交互键时，保持原结构对照；不能通过删掉键来伪造与来源相等。新增静态忽略诊断与图表能力验收分开。

同后端确定性样本可以核PNG/场景字节；跨后端核内容、数据、图元、几何和可读性。现有词云字体占位契约及其原始精确差异保持，不通过提高容差掩盖DSL数据损坏。

### P3：全分组首跑、集中归因修复

首次完整运行收集所有分组退出码再修，分开归因：语法、lowering、字段审计错误、provider既有限制、资源、渲染、对照/工具、原版缺陷。每次修后先相关复跑，保留初次失败；不得把改过的夹具或源码冒作首次运行。

新增的每条语法糖至少有同义通用写法对照和独立预期；不能用同一个lowering函数生成两边预期。所有产品修改重开相应文件租约，公共文件继续单owner。

### P4：同候选最终全量

1. 所有owner停写，归档完整产品/测试/工具字节、原始输入/资源、正式依赖版本与文件SHA。
2. CPU/auto/GPU分别执行完整225规格DSL矩阵与68手写/代表路径；对比同候选spec API，避免把旧候选结果与新编译器混用。
3. 运行全部受影响旧套件：bootstrap、dependencies、flowchart四切片、math、bulk、HTML静态控件、pixel_compare、tooling与现有VChart接入。此前22条故意重现缺口的核实套件继续独立，不冒充绿色回归。
4. 每类型代表静态五格式，覆盖三后端；对确有资源/特殊绘制路径的类型另核SVG/PDF，禁止整图PNG冒充矢量。下载附件须核实际保存字节。
5. wheel/sdist从新环境正常解析PyPI，完整68类型；确认Math/ELK和类型清单未被新入口污染。运行期产品/测试/工具不变，发生变化则该候选不可作为最终结论。
6. 实际看图覆盖68类型代表与全部高风险语法糖/资源/布局案例；源图同SHA复用须回指曾实际查看的收据，不把哈希绑定称为新看图。

具体方法数/用例数以P2冻结清单为准，不在设计阶段编造已通过数量；225与68是既有规格/类型基线，分组中来源重叠须说明。

### P5：分页报告与交付

新建“第六轮 · VChart DSL”报告，至少分组展示：225编译结构等价、68类型实际渲染、手写语言特性、负例/限制、导出与安装证明。每页最多12例，首页只给分组与结论，不拼成长报告。保存 `.vchart`、编译spec、来源span、资源和实际图片/导出；逐字节及HTTP SHA核对。

标准工具使用 `run_support.Run`；参考现有 `run_vchart_validation.py`、`verify_vchart_install.py`、`run_vchart_delivery.py` 的闭合/指纹/失败保留方式，DSL专用runner需记录真实分母。当前发行渠道是PyPI，不能复用旧报告生成器里历史 `PyPI blocked` 字样作为当前状态；旧报告保持原样。

机器汇总、实际看图、报告QA、能力表与文档同步后才可标 `declared_static_scope_accepted`。新语法属于py-mermaid本地产品变更；是否发布py-mermaid包为后续独立任务，本计划不自动发布它。
