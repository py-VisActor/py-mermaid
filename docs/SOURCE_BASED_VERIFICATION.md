### A/B 比较的有效对象

语义字段/异常、配置、节点/组/端口、标签内容和测量输入、布局/路由、解析后样式、绘制指令和输出是有效比较对象。动态 ID 可以做可追溯映射，原始文件仍保留。DOM/React 树、选择器次数、浏览器调度是被替换的机制，不要求 Python 重现。

官方浏览器可以作为研发 oracle 采集边界/计算样式；生产不得使用采集尺寸、路线或样例坐标布局。字体、图标、图片和数学资源要固定版本/许可/hash。py-elk 使用独立项目基线，不要求回退到 Mermaid 旧 elkjs；对应布局差异要在适配/算法来源中登记，不能把另一版本结果静默冒充同一基线。

用户已授权采用 py-elk 替换旧 elkjs，故旧 0.9.3 几何用于来源比较而非强迫回退的目标。P2 将 Mermaid 语法/配置/表现 profile、py-elk 适配契约、ELK 0.12.1 对应计算参考分开登记，复用独立 py-elk 已有的同基线证据并对本项目适配新增单测/集成用例；不把新 Python 候选自身输出当独立期望，也不为套旧坐标写补偿。

原始 RGBA、尺寸、字体和差异报告完整保存。跨浏览器/Canvas 按功能、实际内容、几何关系和可读性判定；字体度量、抗锯齿、亚像素、自然尺寸/合理坐标路由变化可以解释后通过，不要求像素零差。SSIM 等只用于诊断/复核分流；单独高相似不能覆盖功能错误。指定 Python 自回归用例只有固定环境并证明确定性后才可选精确像素；GPU/CPU 不互为零差异基准，随机默认与 seed 回归分开。

## 5. P3 统一排查与修复

P3 先按公共模块和图种分组运行 P2 已写好的测试，对环境/设备/格式做定位问题所需的代表性检查，不在每组后跑全平台全量。首轮分组结果冻结为可复查批次，按“共同根因 → 公共模块 → 图种/专用算法 → 资源/平台/包装”归并。先解决一处会影响多种图的配置、单位、标签度量、顺序或坐标变换，避免按截图逐个打补丁。

每个问题记录：`issue_id / assertion_ids / affected_features / failing_candidate / severity / symptom / root_cause_or_hypothesis / module_owner / allowed_paths / fix_commit-or-tree_sha / changed_surfaces / regression_set / evidence / remaining_risk`。尚未定位时写 hypothesis，不能将猜测当修复结果。

| 优先队列 | 典型问题 | 修复与复核范围 |
| --- | --- | --- |
| 0 安全/执行阻断 | 非法输入导致执行脚本/任意资源访问、挂死、公共 import/契约接线错误 | 安全/核心 owner 先处理，保留失败后回跑攻击/阻断用例及实际受影响入口 |
| 1 公共语义/测量 | 默认 ELK、配置覆盖、UTF-16、稳定顺序、字体/label box、主题颜色 | 公共模块 owner 单点修复；回跑相关公共单元及引用该面的图种 |
| 2 专用算法/图种 | grammar/模型、COSE/tidy/其他布局、图形端点或 marker | 对应 owner 修复；算法边界单元加上所有已知受影响图种 |
| 3 资源/导出/平台 | 缺字体、CJK/RTL/emoji、SVG/PDF 静态字体/页/文字与路径、GPU/CPU/no-loader、并发 | 资源/Canvas/打包 owner 按真实平台和后端复核，不用 CPU 结果替代 GPU |

并行修复采用不同路径单 owner 和接口变更通知；公共模型/样式/布局协议变更由其 owner 提供影响清单，其他角色只修自己的调用侧。统一集成后才更新候选和结果索引，不能让多个 agent 同时修改公共文件或互相覆盖报告。

每次修复只执行该变更的单元用例、直接受影响上层用例、同根因负例及适用设备/格式检查。影响范围来自 source map、模块调用和 assertion 关联；不能只看改了哪个文件。公共变更影响多个功能就扩大相关集，不等于每个补丁重跑全部测试。

修复判定必须绑定新源码/候选 SHA 和实际结果。补丁后原功能/质量错误消失、对应控制仍有效、没有引入同范围回归，才能关闭问题。正常引擎差异按已授权规则分类通过，无须修改代码消掉不同像素。缺资源/硬件记未验，未解释异常保留复核；不能改 golden、裁掉内容、逐元素扭曲对齐或放弃功能硬断言来消除失败。

## 6. P4 最终完整矩阵

P3 的相关回归完成后，建立最终源码树和实际候选包，固定全部依赖与资源身份。对同一候选执行下列完整矩阵，矩阵不等于机械地把每项做无意义笛卡尔积：适用性由原功能契约登记，任何不适用或未验都要有理由。

候选内 README、许可/资源清单与示例代码在 P3-05 收口；P4 固定实际字节，P5 核对交付。若 P5 改了会进入 wheel 的文档/元数据/资源/代码，应构建新候选并回 P4，不能沿用旧候选报告。

| 维度 | 完整范围 |
| --- | --- |
| 功能分母 | 38 个 detector、error/frontmatter 诊断、13 项跨图能力，全部已展开断言和待解决来源 |
| 输入/配置 | 所有 grammar 正负输入、检测/别名、schema/default/主题/look、资源/安全、特殊 JS 值、UTF-16/日期/locale |
| 布局与绘制 | 默认真实 ELK、显式其他布局/选项/插件，组/端口/反馈边/路由/label/形状/marker/裁剪、专用算法与 seed |
| 标签与字体 | 普通/HTML 含义/Markdown/math；同字体、fallback、缺字体、CJK/RTL/emoji/组合字符和度量边界 |
| 导出 | 所有宣称格式 PNG/JPEG/WebP/SVG/PDF，尺寸/density/透明/背景、页/字体/文本/静态格式结构（交互链接与事件元数据排除）；有损编码与向量栅格化单独规则 |
| 平台/设备 | CPython 3.13，Windows AMD64、Linux glibc 2.28+ x86_64；默认 auto、CPU、GPU-required、no-loader 的适用场景 |
| 生命周期/可靠性 | owner 线程、worker 自建对象、连续/并发、取消/异常恢复/GC、空/大/深输入、时间/内存资源上限与性能基线 |
| 包与离线部署 | 同一新 wheel 仓库外隔离安装，无 Node/浏览器/JS/`.local` 或隐式下载；实际包内容、入口、依赖/native/字体/资源 SHA 与第三方许可 |
| 文档与可见交付 | 双语 README、API/支持状态、真实各图示例、原始输出与图片来源、已知差异和运行说明；未验项不宣传可用 |

GPU-required 失败不得回退 CPU 后标通过；Canvas `engine` 状态不能独自证明所有 native 绘制路径。系统字体不未经许可复制；Linux 或 no-loader 未执行就继续标未验。已知 Windows SVG/PDF 并行非确定性等边界须公开，诊断用线程环境变量不得变为隐藏默认设置。

最终完整运行发现问题：冻结原失败 run → 返回 P3 按根因修复并做受影响回归 → 形成新候选 → 重新运行最终完整矩阵。不要在完整验证中每发现一个失败就立刻重跑全套；先汇总能继续采集的问题。任何源码、构建、依赖/native 或相关资源字节改变，都不能沿用前一个候选的完整通过结论。

P4 退出要求：全部保留功能与渲染内容/几何质量/安全导出断言有归属和通过证据；无未实现 stub、隐藏失败/skip 或未处理来源缺口，必要环境和候选身份可复核，待复核异常有结论。`expected_renderer_variation` 不算失败或 skip，图像可以存在非零差异；不要求跨 DOM/Canvas 像素完全相等。

## 7. 证据与交接格式

每次执行写入新的 `test-runs/<run-id>/`，保留 `manifest.json`、实际命令/退出码、stdout/stderr、输入包、A/B 原始结果、比较结果/差异图、问题快照及各自产物 SHA。文件已存在时换 run-id，不覆盖历史失败。任务记录引用这些真实证据，修改后的源码不能冒用旧报告。

交接至少列出：当前 P 阶段、最后冻结源码/候选、源码完成范围、尚未展开来源、测试工具实际入口、未完成断言/问题、当前模块 owner/路径租约、可立即并行的任务、环境/资源缺口、下一步及退出条件。`code_complete_unverified`、单元通过、相关回归通过、最终完整验证通过、发行验收、真实发布分别记录。

P4 之后才能进行发行接受与实际发布步骤；授权、远端 CI、Release/PyPI 和下载核验各自独立记录。本方案没有授权自动发布，也不将当前仅有的 bootstrap 与依赖审计成功计入 Mermaid 功能通过。
