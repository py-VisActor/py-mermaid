# 渲染一致性：功能一致，跨 DOM/Canvas 不要求像素相等

2026-11-04，用户明确：**DOM 与 Canvas 的实现不同，功能上要一致，渲染不用完全像素一致。** 本文是渲染验收的当前权威规则，替代旧文档中容易被理解为跨渲染器零像素差异或零坐标差异的门槛。机器策略见 [render-validation-policy.json](../references/render-validation-policy.json)。

执行阶段不变：P1 先写完全部功能源码，P2 再设计和实现完整 Mermaid 测试/采集/比较工具，P3 分组排查和统一修复，P4 最后全量。用户本轮要求的独立 [PNG 像素工具](../tools/PIXEL_COMPARE.md)已经提供；它不是完整的 Mermaid A/B 语义/渲染比较器，也不代表任何图种通过。

## 1. 四层检测，各自回答不同问题

| 层 | 检测对象与方法 | 判定规则 |
| --- | --- | --- |
| L1 功能/语义 | 将原实现与 Python 的 parser/DB/model/config 规范化，比较节点/边/分组、内容、关系、方向、形状类别、配置和错误 | 保留的功能、内容和约束必须一致；差异是失败，不能用图片相似度抵消 |
| L2 绘制结构 | 按语义 ID/角色比较实际绘制场景，核对节点/连线/箭头/标签/图标、层叠意图、主题/字体/线型等解析后样式 | 关注“画了什么、表达什么”，不比较 DOM 节点树或 Canvas 调用次数；缺失/额外/错绑元素失败 |
| L3 几何关系与可读性 | 检查方向/排序约束、分组包含、端口/端点连接、标签可见/容纳、意外遮挡、viewport/显式尺寸等 | 坐标和自然尺寸可随度量改变；违反语义约束、内容裁切/消失、错误连接、不可读输出必须失败 |
| L4 图像诊断 | 保存原始 A/B 图像及环境，产出并排图/差异图、相似度/局部异常等指标 | 像素差、SSIM、感知相似度用于定位/预警，不单独决定功能通过或失败；不要求跨引擎零差异 |

其中 L2/L3 是“渲染功能一致”的核心。只比较 AST 不足以发现“模型有文字但实际没画”；只比较图片也容易让大面积背景掩盖漏箭头、漏字等错误。

## 2. 从 A/B 获取可比较的数据

同一 case 固定原始文本、配置、明确字体/资源、seed、语言/时区、viewport/scale 等输入。字体尽量用同一可再分发文件和 SHA；实际 fallback、设备/driver、密度和布局版本各自记录，不能把不同环境误称同一环境。

开发参考 A 使用固定 Mermaid JS/browser：

1. 从 detector/parser/DB/config 取得语义与有效配置。
2. 由各图种采集适配器，把 SVG/DOM 中的节点、边、marker、标签等映射为**语义场景记录**，读取实际样式/边界/路由；不以 DOM element 总数作为图形元素总数。
3. 展开 SVG/DOM transform 并转换到统一逻辑图坐标，记录图像像素和逻辑坐标间的真实 scale。保留原始数据和原始 PNG。

Python B 从自身实现取得：

1. 语义模型、有效配置、解析后样式、真实 Canvas 测量的 TextRun/LabelBox。
2. 布局结果与类型化 DisplayList，按语义对象 ID/角色关联到每条绘制指令及资源。
3. 实际 Canvas 绘制/编码的结果与输出 PNG，记录后端、尺寸、资源与候选身份。调试记录的 API 名称在 P2 实现时确定，不把它们当成现在已有接口。

两边规范化为拟定的 `SemanticScene`：

```text
case/config/resource/candidate identity
element: semantic_id, role, owner_id, text-or-content, shape-kind,
         resolved-style, bounds, parent-group, ports, z-order intent
edge: source-id/port, target-id/port, direction/marker, labels, route
viewport: logical bounds, requested/final dimensions, density/scale
capture: completeness, unmatched/ambiguous elements, fonts/backend/version
```

动态 ID 按原始语义身份、源位置或可追溯的一对一映射处理；平行边、同名标签、重复图形不能被集合去重吞掉。无法匹配或采集缺项属于 `REVIEW`/`UNVERIFIED`，不能默认为空集合后判通过。

这些数据只供测试/诊断，生产仍完全依赖自身输入、Canvas 实测和布局计算，不读取 A 的尺寸、路由或坐标来生成 B。

## 3. 必须一致的内容与允许变化的表现

| 必须保持 | 允许的引擎表现差异（仍需满足功能/质量规则） |
| --- | --- |
| 节点/边/标签内容与关联、分组归属、箭头方向、实际图种含义 | 节点绝对坐标、自然画布尺寸、没有语义顺序约束时的相邻节点摆放 |
| 用户指定的方向、排序/端口/分组/布局选项含义 | 因文字测量导致的节点宽高、间距和路由控制点调整 |
| 主题/配置要求的填充/描边/字体/颜色等样式含义 | 字形 hinting、边缘抗锯齿、亚像素取整、少量字距/基线差异 |
| 普通/富文本/数学的内容、样式 run/操作符语义、资源身份 | 不丢字、不截断且满足宽度约束时的合理换行/排版差异 |
| 显式要求的输出尺寸/scale/background、适用元数据和安全拒绝 | 未显式固定尺寸时，满足内容包围盒与 padding 的自然尺寸差异 |

颜色差异不能一律作为“抗锯齿”放行：解析后的主题色、线型、透明度等仍应符合配置，只有 raster 边缘/合成等引擎表现按相应 profile 解释。字体 fallback 若符合已声明策略且字形完整可接受；乱码、缺字方框、数学符号遗漏是功能/质量失败。

DOM 与 Canvas 的 `getBBox`/字体测量结果不要求数值相同；B 自身“测量→布局→绘制”必须自洽。比如节点变宽可以接受，但标签超出节点且被裁掉不接受。普通 TD 图检查有效层级的上下关系；环/反馈边/自环采用对应图种规则，不能要求每条边都严格向下。分组包含和有意叠放也不应被通用“不许重叠”规则误判。

## 4. 自动判定与问题分类

- **PASS**：全部必要 L1/L2/L3 与导出/安全检查通过；存在可解释的预期引擎差异也可以通过，无须因每个不同像素再次请求确认。
- **FAIL**：漏/多元素、内容/关系/箭头错误、配置含义错误、裁切/不可读、错误资源或安全行为、显式尺寸不符等。即使 SSIM 很高也失败。
- **REVIEW**：采集/元素映射存在歧义，或出现尚未解释的大面积/局部图像异常；保留原因与证据，完成定位后按功能/质量规则决定，不直接按像素数否决。
- **UNVERIFIED**：缺字体/环境/候选身份/必要场景或真实输出证据，不能记通过。

P2 将每个规则写成有 ID 的 profile：适用图种/元素、比较字段、逻辑单位、数值精度、允许差异类别、失败条件和来源。**不设置一个通用于所有图种的 SSIM 门槛，也不在看到失败后随意抬高阈值。** 如需图像预警阈值，使用明确正常的跨引擎样例与故障注入对照校准，并版本化固定；阈值只影响预警/复核队列，不覆盖功能硬断言。

比较时可以依法转换坐标系/密度及制作带说明的诊断图，但原始图保持不变。不得裁掉丢失内容、逐元素扭曲/移位对齐或修改 golden 来制造相似度。自然尺寸变化用场景关系判定，显式尺寸约束仍精确检查。

## 5. 如何保证真画了，而不是只在模型里存在

L2 的 DisplayList 不能成为唯一证据。P2/P3 需要：

1. Canvas adapter 的独立边界用例，证明路径、文字、图像、clip/transform/样式等实际产生对应区域的可见内容；复用公开 Canvas API，不重新验收整个 Skia。
2. 最终 bytes 能真实解码，尺寸/透明背景正确，图像非空；按场景位置检查应有内容区域、裁切与图像边界。规则区分节点背景、边、文本及有意留白，不用单一前景像素比例断言整图正确。
3. 以固定 Python 后端的受控小例验证“漏画文字/箭头/图像”等故障能被检测；必要时用测试专用的元素/文字层诊断定位，诊断产物与最终原图分开保存。
4. 对自动检查仍有歧义的复杂标签、公式和明显视觉异常进入复核；人工只处理待解释项，不能替代全部自动功能断言。

OCR 可以作为异常提示，不作为标签内容的唯一 oracle；模型/文本 run 核对实际内容，native 绘制边界和输出检查证明执行路径，图像检查与复核补充发现表现缺陷。

## 6. 跨引擎对比、计算单测和自身回归分开

| profile | 目标 | 像素/数值要求 |
| --- | --- | --- |
| `dom-vs-canvas-functional` | 原 Mermaid 与 Python 的功能/内容/表达一致 | 不要求像素、绝对坐标或自然尺寸相等；按 L1/L2/L3 判定 |
| `algorithm-unit` | 所保留纯数值/布局/几何算法及 adapter 的正确性 | 同输入/同算法版本下按独立期望和明确数值精度验证；不因图像放宽而放弃算法检查 |
| `canvas-self-regression` | Python 自身后续修改是否产生回归 | 只有固定字体/seed/尺寸/后端/driver且证明确定性的指定用例可启用精确像素；其他仍按功能/质量与记录的环境差异判断 |

GPU/CPU、不同 driver/字体/平台不互作零像素差异基准。用户授权的 py-elk 基线替换也单独记录，旧 elkjs 0.9.3 几何不是要求 py-elk 回退的目标。跨引擎“一个像素不同”只产生诊断；精确像素自回归 profile 的单像素破坏才应触发失败。

## 7. P2 必备的正/负控制与报告

L4 的通用像素部分已有 [pixel_compare.py](../tools/pixel_compare.py)：输出精确 RGBA/alpha-composite 指标、差异包围盒/局部 tile、热图、掩码、离线 HTML 和 SHA 报告。默认 diagnostic 模式只报告，不因不同像素返回功能失败；exact 仅供满足条件的自身回归。完整用法/输入限制见 [工具文档](../tools/PIXEL_COMPARE.md)，SSIM 与语义区域汇总仍待 P2 选配/实现。

需检出：删除节点/边/标签、箭头反向、文本/公式符号替换、分组归属错、端点脱离、内容被 clip、主题样式/显式尺寸错误、Canvas 文字/路径 no-op、恶意资源放行。每种错误用对应层断言定位，避免只靠整张图片。

需放行：仅抗锯齿/亚像素变化，合法文字度量导致的节点宽度/自然尺寸变化，未违反配置/拓扑/可读性的路由与坐标变化。放行仍要求真实内容/质量检查通过；故障注入样例不能只是通过改结构数据宣称正确，而不验证实际绘制。

报告分开给出 `functional_status / render_structure_status / geometry_quality_status / export_security_status / visual_diagnostics / review_items / overall_status / policy_version`，保存完整 A/B 数据、原图、差异图、候选/资源/环境 SHA。允许的引擎差异记 `expected_renderer_variation`，不是待修 bug 或隐藏 skip。P4 最终全量要求功能与质量规则完整通过及待复核项有结论，**不要求 A/B 的像素差为零**。
