## 2. 固定基线与完整范围

- Mermaid **12.2.0** / `1fb7869866dd619168d840291c9c54b4f129758b`，只读源码 `.local/upstream-mermaid`；[来源锁](../references/upstream.lock.json)不变，不跟随在线最新版或改 SHA 掩盖漂移。
- ELK 复用独立 `py-elk`，分发名 `py-visactor-elk`；已发布 0.1.0，不因 Mermaid 的 elkjs 0.9.3 而回退其 0.12.1 基线。Mermaid 模型、选项、端口、标签和路由适配仍属本项目工作。
- 测量、字体 shaping、绘制和编码仅调用 **`py-skia-canvas==0.1.0a18`** 公开 API；首轮 CPython 3.13，Windows AMD64 / Linux glibc 2.28+ x86_64，最终分别验收。
- 生产不依赖 Node、浏览器/Playwright、JS 解释器、skia-python 或 `.local`。开发 oracle 在 P2 之后使用固定官方 JS/browser。
- 淘汰 DOM/虚拟 DOM、D3 selection、fastdom、React 浏览器层、通用浏览器 CSS 排版与 HTML 截图。保留图语言、模型、配置含义、所用算法和图形表达、资源/安全及适用元数据。
- 完整覆盖 **37 core detector + ZenUML**，另保留 `error`/`---`、全部 **13 跨图能力**、配置/主题/look、布局插件和扩展注册、所有目标导出。F01.1 首图不是完整迁移终点。
- 上游索引现有 368 个测试源文件、2,366 个渲染 fixture、38 grammar、34 syntax 文档。这是文件分母；正式 case/assertion 分母在 P2 展开，不是当前覆盖率。

  → Python 预处理/检测/语法/语义模型

  → Canvas 实测文字 + Python 节点/标签尺寸

## 3. 阶段顺序与硬门禁

| 阶段 | 工作 | 退出条件 | 状态含义 |
| --- | --- | --- | --- |
| P0 接管/边界 | 备份脏树、校验来源、登记范围、模块/接口责任、候选依赖和资源约束 | 任务可分派、来源和边界明确、已有修改保留 | 准备完成，产品仍未实现 |
| **P1 全部功能源码** | 协议先行，各图种并行编写，公共模块随需求扩建，完成 API/CLI 与全体接线 | 所有范围均有真实实现；编译/导入/引用/签名/注册等机械检查完成，无缺失实现或成功 stub | **`code_complete_unverified`** |
| **P2 来源测试设计/编写** | 原实现/spec/grammar/fixture → case/assertion；单测、功能测试、oracle、比较器与负控制 | 来源归属完整、测试工具可编译/收集，期望独立可追溯 | 测试写完，不代表通过 |
| **P3 排查/统一修复** | 分组首次运行，保留失败、归类根因，优先公共原因，再修图种，按影响面复跑 | 已发现问题闭环，相关修复证据齐备，冻结最终候选 | 增量通过，待最终矩阵 |
| **P4 最终全量** | 同一候选的全部 case、平台/设备/字体/导出/安全/生命周期/部署矩阵 | 无隐藏失败/skip/open/未验，源码/候选/环境/证据一致 | 全量通过后才作完整兼容结论 |
| P5 交付/发行 | 真实例子/图片、文档、许可资源、包内容、隔离安装，按实际授权执行外部动作 | 交付与候选相符，commit/push/CI/发布/回读各有真实结果 | 每个外部动作独立记录 |

**P1 是覆盖全部功能的一整个编码阶段，可以分并行波次和多次源码提交；不是一个巨型提交，也不是仅完成基础流程图。P2 必须等待全部 P1 源码收口。**

P0/P1 可以读原实现、配置/schema、grammar、算法，明确接口、输入输出、错误语义和来源映射。这是编写源码必需的契约，不提前建设完整测试用例/单测，不运行逐图功能回归，也不要求官方图像对照通过才写下一功能。

P1 仅做语法/编译、必要的无副作用 import、符号/签名/注册、依赖与包引用等机械检查。既有 bootstrap/source 工具可以保护资料；这些检查不构成 Mermaid 功能测试。缺少 native 环境时记录具体未完成机械检查并继续无关源码，不能伪造通过。

源码缺口必须保持 `code_incomplete`/实际阻塞，不能用 NotImplemented、固定样例坐标、白图、吞异常或万能 fallback 掩盖。合法的抽象协议、显式输入拒绝与来源本来存在的错误不算 stub；正式判断要检查所有实际产品入口。

## 4. 公共模块职责与增量扩建

详细目录和接口以 [MODULE_BOUNDARIES](MODULE_BOUNDARIES.md) 为准，责任划分为：

| 责任 | 主要内容 | 扩建方式 |
| --- | --- | --- |
| C01 配置/诊断 | schema/defaults/merge、JS 值、主题配置、位置/错误；预处理/位置映射与 C02 协同 | 新图种提出具体字段/默认/错误要求，由 owner 扩展，不复制配置管线 |
| C02 解析基础/注册 | 预处理、detector、parser 协议/词法支撑/spans | 专用 grammar 留图种目录，共用预处理/注册/错误能力集中维护 |
| C03 语义/图数据 | 有序节点边、复合图、模型/测量/布局/绘制协议 | 共享类型仅表达跨图语义，消息/成员/时间等专用数据留图种侧 |
| C04 标签/主题/排版 | 普通字、Markdown/富文本/数学、颜色/样式、测量协议 | 普通标签先支撑流程图，其他图种继续扩建公共文本模块 |
| C05 布局/路由 | ELK adapter、Dagre、树/力导向、Sankey/Venn/专用布局 | 引擎隔离，统一尺寸/几何协议；专用策略仍由各图种负责 |
| C06 几何/数值 | path/shape/intersection/marker、D3 所用数值、Rough | 复用具体算法，不复制 DOM 或 graphlib API，不堆入 common.py |
| C07 Canvas/输出/运行 | 唯一 native adapter、绘制指令、格式、设备/owner、入口编排 | 图种输出指令，新 primitive 通过 owner 增量加入 |
| C08 资源/安全/元数据 | 字体/图标/图片、离线访问、URL/标签策略、链接/a11y | 统一策略和资源入口，图种不自行下载或复制另一套清洗逻辑 |

只有 Canvas adapter 创建/持有 Canvas、Context、Font。公共计算不引用图种实现；图种消费公共协议；parser 不分配 Canvas。公共模块扩展以 `requests/common/<id>.json` 或等价任务记录交接（执行期拟建），包含消费者、来源、行为、输入输出、owner、兼容影响和任务依赖。

每个路径同一时间只有一个写 owner。消费者提出需求后继续写自身无冲突源码，由公共 owner 扩展；不跨目录抢改。优先兼容的字段/类型扩展，破坏性接口变更由主协调安排集中窗口并同步全部消费者。复用不足在后续图种中修正，公共模块始终允许扩建，不追求第一轮抽象完美。

## 5. P1 的首条主线与并行开工

先写核心数据协议，随后基础流程图沿 `parser/model → 样式/标签度量 → py-elk → 绘制指令 → Canvas PNG` 组装源码；其作用是暴露共享职责和接线需求，正式功能/图像验证统一后置。

协议确定后，关系图、时序图、时间/数值图、树/流量/集合图、结构/业务图、语法图和 ZenUML 可并行编写。公共 owner 同期完成它们需要的算法、标签和资源。不会等待“完整 flowchart 测试通过”或“整个 D3/HTML/math 全部完成”才开放其他图种源码工作。

机器任务图区分：

- `dependsOn`：可开工的真实前置，例如模型/接口冻结。
- `integrationNeeds`：最终接线必须齐备的实现；接口明确时不阻塞作者提前写源码。
- 全源码集成：等待全部公共能力、图种和入口完备，再完成引用、签名、注册和装配。

默认 **4 槽 = 主协调/集成者 + 3 worker**，角色随波次复用；更多槽按独立目录扩展。具体分组/角色/回执/分派模板见 [PARALLEL_EXECUTION](PARALLEL_EXECUTION.md)。公共协议冻结后，尽量从 ready 队列调度，避免无关工作等待同一长任务。

每个波次只复盘新增公共需求、源码完成面、冲突/等待、未实现点和下一队列；P1 不重复全仓功能验证。任务不能因“等待测试”被占槽挂起：正式测试尚未进入当前阶段。

## 6. P2–P4 的闭环

渲染接受规则由用户明确为 [功能一致、非像素一致](RENDER_CONSISTENCY.md)：L1 语义、L2 实际绘制内容、L3 几何关系/可读性是硬门禁，L4 图像差异作诊断。正常引擎差异可通过，无需逐像素消除；最终全量要求功能和质量完整覆盖，不要求图片零差异。

P2 在 P1 全部源码快照后，根据固定原实现独立设计测试。368 个测试文件之外补查 `import.meta.vitest`、非标准命名、动态/参数化用例、snapshots、fixture 配置/资源及公开 helper。期望来自上游行为/实际输出；不能把 Python 新实现的输出存成唯一 golden 再自证正确。

ELK 已由用户明确采用独立 py-elk 替代旧 elkjs：原 Mermaid 0.9.3 的几何输出保留作来源对照，不能反过来要求 py-elk 回退。P2 为语法/配置/图形表达、py-elk 适配与其 0.12.1 基线计算分别建立来源明确的 profile，记录版本替换造成的差异；不能将两套版本输出混称同一 oracle，也不能借版本替换忽略适配错误。

测试按纯单元、模块组合、图种功能、跨图配置、安全/资源、渲染与导出、生命周期/平台分层。上游 DOM 树是诊断资料，不要求 Python 复制；比较语义/错误、样式与文字/node box、布局路由、原始像素和导出结构。

P3 先分组运行并汇总初始失败，再按公共根因批修：值/顺序/单位 → 配置/解析/模型 → 度量/样式/几何 → 布局 → 图种专用 → 导出/生命周期。独立根因并行修改，共享文件仍由唯一 owner 负责。通过影响清单增量复跑，不反复运行全平台/全图片矩阵。

P4 最后执行完整矩阵。若有失败，保留本轮报告，回 P3 修改相关根因；新候选仍需重新完成最终全量，不把不同源码/wheel 的局部报告拼成全量成功。缺平台、字体或设备时保留未验，继续无关工作，不能计通过。
