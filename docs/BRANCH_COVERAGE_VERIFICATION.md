## 执行顺序与分工

1. P0：保存起点脏树、候选和旧未决范围；root+A/B/C 只读固定源码，冻结具体分支目录与独立用例合同。
2. P2：在不执行产品行为的条件下编写新增测试/fixture。期望取自固定原版源码/spec；记录 path、symbol、行、SHA、条件和断言，不从 Python 输出反推期望。
3. P3：冻结产品/测试/工具后统一首跑，保存真实退出码和所有原始差异。来源原版采集使用已有离线开发环境；没有生产浏览器、Node 或 JS 回退。需要原生内容、状态或几何的断言，不能用渲染成功或像素相近替代。
4. P4：汇总每个具体分支的来源、断言、实际执行及结论。已有验证仅在候选与断言完全对应时复用，旧 865 例证据不冒称覆盖新增分支。无产品改动时不重复完整渲染/导出矩阵；对新增输入做必要的 CPU/auto/GPU 和原版对照。
5. P5：保留未通过和证据不足，输出核实报告及待修复清单；新增图像按第四轮分页展示，旧报告不覆盖。更新交接和标准变更收据，不提交、推送、安装或发布。

A：模型/结构图的语法、字段消费者、block 链及元数据。B：日期/格式/刻度、Git、Agentflow、Wardley 和数值布局分支。C：Sequence、Zen、ABNF、info主题及 Swimlane 路由。root：共享配置/主题/资源/安全、来源范围判定、证据集成与报告。
