# 文档分工与维护规则

## 三个入口

| 入口 | 读者 | 内容 |
| --- | --- | --- |
| `README.md` / `README.en.md` | 第一次了解项目、GitHub/PyPI 访问者 | 简介、安装、最小示例、核心能力与限制、用户文档及反馈链接 |
| `docs/README.md` / `docs/user/` | 使用本库的应用开发者 | API、CLI、语法、配置、资源、平台、排错与可运行示例 |
| `AGENTS.md` / `docs/development/` | 修改仓库的维护者、AI coding agent | 稳定规则、目录职责、开发命令、来源验证、测试、发行和状态记录 |

向应用开发者解释库的使用属于用户文档；指导 agent 修改仓库属于研发文档。README 只给一个简短开发入口，不展开迁移轮次、日志、阶段计划或本机报告。

## AI 入口

统一使用根目录 `AGENTS.md`，不再创建 `agent.md`、`AGENT.md` 等并列入口。六个部分依次为适用范围、开始工作、仓库地图、常用命令、修改约束、验证与完成条件。按需链接详细开发规则，避免复制完整测试方案或堆叠进度时间线。

版本、实际发行、当前任务和授权分别读取对应元数据、凭据及当前会话；AGENTS 不长期写死历史用户目标、旧授权或验收数字。旧计划不会自动变成新任务。

## 链接、历史与发布

- README 和 PyPI 展示中的仓库链接使用完整 GitHub URL。`project.urls.Documentation` 指向用户文档索引，不指向 AGENTS、NEW_SESSION 或交接文件。
- 用户语法、API 和参数只维护一份正式参考，旧路径保留短导航。历史计划、验收、原始图和收据保持原字节，需整理时建立可验证的归档。
- 不把待实现计划、注册数量、代表性示例或工具退出成功写成完整兼容承诺。公开限制用用户可理解的行为描述。
- 已发布 PyPI 版本的描述和元数据随发行固定；仓库编辑不会更新该版本。需要更新线上包页面时发布新版本，不覆盖旧文件或移动 tag。本次仅整理文档和后续发行元数据。
- 文档纯改运行链接、Markdown Python 片段语法、公开 API 签名和相关元数据检查；不重编依赖、不重复渲染/安装矩阵。新增绘制示例或改变产品行为另按影响验证。
- 本轮文档变更会改变 README/元数据指纹；旧发布收据继续绑定旧提交，不能将其源 SHA 替换为新工作树的 SHA。
