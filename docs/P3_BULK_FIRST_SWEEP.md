# P3 全分组首跑与批修

前置：A/B/C/shared 的 P2 测试设计回执、fixture 来源 SHA、机械发现全部收齐。
初次产品行为执行保持 P1 候选 `97b353ebf7e176a750a736a714c85638e0a497b722e451dc77570579a2d36cbb`。

统一执行 `python tools/run_bulk.py first`：先 A/B/C/shared 与 F01/数学分组单测，再固定官方 A、
各组 CPU 原生 B、配置/可见内容比较、像素诊断与 HTML。遇到失败继续其他组，保存真实错误和部分进度。
首跑 sweep 尚未关闭时，产品文件全部只读，避免把中途修复混入首次候选。

首跑完成后按根因归类：解析/DB、配置主题、布局约束、Painter/标签/资源、平台环境、测试绑定/工具、
固定上游缺陷与用户排除。每项绑定失败 case、原始日志、上游符号与文件 SHA。
测试预期来自固定源；若原断言理解错误，保留旧失败并用源证据解释修正，不能因产品不支持而缩分母。
源未消费元数据和源缺陷必须与官方原图/错误相互印证；源接受的扩展不冒称为源语法负例。

批修期间恢复单文件唯一 owner：A/B/C 各自产品模块，root 独占公共模块和工具。
公共疑点由 owner 发给 root；同文件修改结束后才能交还。专门泳道路由仍归 C，B 集成调用。
修复后先相关复跑，再冻结新候选与新日志；成功不能覆盖初始失败。
